# Live Select COMP integration parity

Historical comparison baseline: `.55.toe`, before independent Device context. The user subsequently approved implementation; current v3 behavior is documented in [Layouts, Tracks and Devices](../functions/layouts.md) and [implementation contract](../plans/device-context.md). Source line links below record research-time positions and may have shifted during implementation.

## 結論與目前狀態

現時 TD 已完成嘅係 **COMP selection → Active Layout 內 linked Track → 該 Track 唯一 Plugin**。Ableton / Bitwig 嘅對應行為係 **Track selection 同 Device selection 分開**；同一 Track 可以揀不同 Device，硬件亦有獨立 Plugin selector。現時 TD 功能符合已批准嘅第一階段 Follow contract，但未具備 DAW Device-selection parity。呢個缺口係 domain / API 層，單純改 `CUSTOM` 或同步 Layout / Plugin 名稱唔會補到。

研究日期：2026-10-07。比較本 repo Ableton script `3.2.0`、Logic script `3.2.10`、Bitwig Java source，同 first-party guides / bundled Bitwig SDK。官方下載頁現時列 `3.3.0`；本次冇下載／安裝新 integration，3.3.0 release-notes PDF 亦未能取得。因此以下係本地 source snapshot 對照，唔聲稱最新版完整 parity，亦冇新增 DAW / 硬件 physical acceptance。[官方下載與版本頁](https://www.melbourneinstruments.com/roto)，[Ableton version](../../../ableton/ROTO_CONTROL.py#L28)，[Logic version](../../../logic/config.lua#L16)。

### 硬件上有三種不同 selection / browsing

- **FUNC：Track selector。** 揀另一條 Track。
- **Hold SEL：Device / Plugin selector。** 揀同一 Track 入面另一個 Device。
- **正常 control view 嘅左右箭嘴：control pages。** 換同一 Device 嘅一頁 controls，唔係換 Device；喺 selector view 嘅箭嘴則係對應 list browsing。

官方 Ableton manual 第 10–11 頁將三種操作分開，亦說 MENU 同時顯示 Track 同 Device 名稱。呢份係 firmware 1.1.4 歷史 manual；下面本地 Ableton / Bitwig source 亦保留獨立兩層 selection，唔係只依賴舊 manual 推斷。[ROTO-CONTROL User Manual](https://www.melbourneinstruments.com/s/ROTO-UserManual-V1-1-4-April2025.pdf)。

## Ableton source comparison

- **Track / Device 各有 selection。** `_update_selected_track()` 讀 selected Track；`_update_selected_device()` 讀該 Track 嘅 selected Device，`_send_selected_device_update()` 送 Device index，同步所在八個 Devices 嘅 bank。Device list 會 traverse nested rack chains，唔止一個固定 Plugin。[ROTO_CONTROL.py L911–959](../../../ableton/ROTO_CONTROL.py#L911-L959)，[L625–648](../../../ableton/ROTO_CONTROL.py#L625-L648)。
- **Host → hardware。** selected Track / Device listeners 分開更新；Device changed callback 有 hardware-origin flag 避免 echo。Track change 會更新 Device list 同 selected Device。[L1010–1089](../../../ableton/ROTO_CONTROL.py#L1010-L1089)。
- **Hardware → host。** GENERAL `09` 寫 `song().view.selected_track`；PLUGIN `07` 經目前 Device-bank offset 找 Device，再調用 `song().view.select_device()`。PLUGIN `04` 只換 Device list bank，唔等於選 Device。[L1395–1416](../../../ableton/ROTO_CONTROL.py#L1395-L1416)，[L1471–1494](../../../ableton/ROTO_CONTROL.py#L1471-L1494)。
- **LOCK 停止自動 Follow，但唔封鎖 explicit hardware Device selection。** Lock 儲存 Track 同 Device；鎖住時 hardware Device select 仍更新 `_locked_device` 並選 host Device。Unlock 清 locked handles，再處理目前 host selection。TD 現時只有 Track intent，唔具備呢個獨立 Plugin-select 例外。[L1478–1493](../../../ableton/ROTO_CONTROL.py#L1478-L1493)，[L1653–1665](../../../ableton/ROTO_CONTROL.py#L1653-L1665)。
- **唔需要完全照抄 fallback。** Ableton 冇 selected Device 時會揀第一個 Device；TD sole-COMP policy 刻意冇 currentChild / first-COMP fallback，係已決定嘅 selection policy，唔係必須修復嘅缺陷。[L923–937](../../../ableton/ROTO_CONTROL.py#L923-L937)，[Follow contract](../plans/live-select-comp.md)。
- **Plugin name 來自 Device，identity 唔一定同 display name 一樣。** Plugin details 發實際 Device name；hash 對支援 preset recall 嘅 Devices 用 class name，其他類型用 class + name，macro racks 有特例。TD 用 stable saved IDs，所以唔應為咗模仿 DAW naming 就改 UUID 或令 rename 必須重新 LEARN。[L1769–1817](../../../ableton/ROTO_CONTROL.py#L1769-L1817)，[TD layouts identity](../functions/layouts.md)。

## Logic source / guide comparison

Logic guide 同樣分 FUNC Track selection 同 hold-SEL Plugin-slot selection：一個 instrument + 15 Plugin slots，Plugin 各有自己的 controls pages。Guide 亦明確講硬件 Plugin selection 預設會開 host Plugin panel，LOCK 可停此 popup 行為；呢個政策同 Ableton / Bitwig routing lock 唔可直接混為一談。[官方 Logic guide 第 2 頁](https://www.melbourneinstruments.com/s/gettingStarted-LOGICxROTO-190226-zd69.pdf)。

本地 Lua `ROTO_CONTROL_SELECT_DEVICE` 保存 slot，調用 `select_plugin()`；只喺 `popup_lock == false` 時另外發 open-window 按鈕指令。由此確認 **routing selection** 同 **UI window popup** 係可以分開嘅操作；唔代表 TD 一定要自動打開 pane / viewer。[config.lua L1070–1086](../../../logic/config.lua#L1070-L1086)。

## Naming 同下一步建議（未實作）

之前提出 Layout name 跟 Plugin name 同步，只解決 display 管理，唔係 DAW hierarchy 嘅對應關係。對要接近 Ableton / Bitwig 嘅 workflow，建議改成：

- **Layout：** TD 保存嘅配置／組合；無同名 DAW Device 層。
- **Track：** 一組相關 tools 嘅容器／group；TD 冇天然 audio Track，要明確指定 grouping policy，唔強制每個 parent COMP 自動成為 Track。
- **Device / Plugin：** 被控制嘅 tool COMP，例如 `pixelSortV3`；display name 可以預設跟 COMP name。
- **Control page：** 該 Device 已 LEARN 嘅 controls 頁，保留現有 index/hash recall 機制。

呢個係 design recommendation，唔係已批准 migration。真正要補嘅第一件事係 **獨立 Device context**：Track 內多 Plugin、per-Plugin Focus link / parameter library、selected/routing Plugin、SEL list / selection / banking，然後 COMP Follow resolve 到 `(layout, track, plugin)`。Public API 可考慮 `GetPlugins` / `CreatePlugin` / `SelectPlugin` / `SetPluginComp`，名稱同完整 contract 要喺新 plan 決定。

Hardware → TD selection 仍應獨立、可選；先決定係只寫 selection，定包含 pane navigation / reveal。UI follow 同 explicit hardware selection 嘅 LOCK policy 亦要分開；新 Device switch 必須延用已完成嘅 batch / backlog / partial-line fences、connection generations 同 LEARN / touch guards，唔好退回逐條 message 即時改 target。

**Migration gate：** 唔可以將現有兩個 mapping variants 自動當成兩個 Device instances。同一個 COMP 喺同一 Layout 唔可以無政策地綁兩個 contexts；必須決定 variant 係另一個 Layout、Device profile，定其他明確選擇。Existing Plugin / parameter IDs、wire hashes、off-page library、Python registration 必須保留，rename 唔應令已學 mapping 失效。

次要 parity 項目係 automatic macro / remote-pages 類 workflow。官方分別提供 Ableton racks/macros、Bitwig Remote pages、Logic Smart Controls；TD 目前以 LEARN / Python registration 為主，未有等價嘅 COMP custom-par auto-bank。呢個可以另做 opt-in 功能，但唔係補 Device selection 嘅前置需求。[官方 automatic mapping FAQ](https://www.melbourneinstruments.com/roto)。

驗證邊界：本次只讀 source / official docs；冇改 runtime、toe / tox、live TD state 或 upstream integrations。冇將 Bitwig / Logic policy 當成 Ableton 全部相同，亦冇聲稱已物理測試新增 Device behavior。

1. **獨立 Plugin / Device selection，同一 Track 多個 Plugin。** Bitwig 最直接多出嘅 selection 層：揀 Device 唔需要先換 Track；Hardware 亦有 Plugin list / bank / select。TD 若要做到呢個 parity，需要 saved Track → 多 Plugin、selected/routing Plugin，同每個 Plugin 嘅 mappings，而唔只將每個 COMP 對應另一個 Track。[RotoViewControl.java L45–50](../../../bitwig/src/main/java/com/bitwig/extensions/controllers/melbourneinstruments/RotoViewControl.java#L45-L50), [PluginModeHandler.java L226–234](../../../bitwig/src/main/java/com/bitwig/extensions/controllers/melbourneinstruments/device/PluginModeHandler.java#L226-L234)
