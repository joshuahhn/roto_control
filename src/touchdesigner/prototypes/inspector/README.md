# Compact real-data Inspector prototype

The current Inspector checkpoint is saved through live TD 2025.33230; use the active project filename for its save version. The earlier `inspector_real_data.toe` checkpoint passed reload verification. Both retain the existing Roto controller and mappings. MIDI starts disconnected after reload; use the existing controller's Connect pulse. The compact UI is separate from the production table Inspector.

## Use

Only one compact Inspector is shown at a time, with its editor collapsed. Click **FOLD ↔ / POPUP ↔** to switch presentation in that same window; Popup opens only when a control is clicked. Opening the alternative Inspector closes the other compact view and its editor. The current checkpoint retains the user's Popup preference.

- **Device** occupies the first selector row; **Layout | Track** share the second. All three open a native TD dropdown panel **inside the same Inspector window**, immediately below the header on release inside. The selected item has a native icon check mark. The panel overlays existing content without resizing the window; it reuses at most eight rows, with wheel/paging for longer lists. Click outside or press Escape to close. No separate header menu window or deferred timer. Selecting a menu item browses the real registry without changing hardware routing. Opening a menu does not cycle; stale selections after a context/session change are ignored.
- The **LIVE** indicator follows the controller's active context. After browsing it reads **BROWSE**; click it to return to the active context.
- The bottom **All controls ▾** menu filters the existing rows by registered target COMP or **Python callbacks**. All controls includes the sixteen empty/assigned slots. Filtering changes only this view; it never activates a Device or changes controller routing.
- The editor's compact **ⓘ Details** button opens bold group headings with muted labels and larger values; long paths/IDs are in its scrollable Technical group. It reveals stable target ID, full target, native Style/mapping Mode, health/error, view-follow state, controller Follow, LOCK, selected/routing context and gate. Details, Mapping and Target picker share the same editor and open one section at a time. RX/TX/rejected counters are sampled on open or **Refresh**. **Reveal** navigates the existing Network Editor pane; turn controller Follow off first because pane navigation can affect its routing. **Repair** opens the existing Target picker and still requires explicit Assign.
- Bottom-right **Clear Device** opens a native confirmation menu naming the complete Layout / Track / Device and registration count. It calls the existing `RemoveAllControls` for all current active registrations, including rows hidden by filters. It preserves target Values, other Devices and inactive hardware-page libraries. This is the existing active-registration cleanup scope, not a whole Device-history deletion. Confirmation is single-use and expires after eight seconds or a context/session/registration/definition change; live Value updates do not expire it. LEARN, touched controls and inactive browsing block removal. Partial failures report removed/remaining counts and the error.
- Click a K/B row to inspect its real Label, Target, Range and Value. Label remains read-only. Click **Target / Choose target ▾** for a searchable COMP-scoped picker; select a result, then use its check icon to Assign. The picker supports empty slots and retargeting on the active Device. Search/selection/cancel are read-only; incompatible targets explain their rejection. Click **MAPPING ▸** to expand Range, compatible Mode and HW Type settings.
- Row markers show mapping health: **● Mapped**, **○ Pending**, **◇ Saved**, **! Invalid / Re-learn**, **· Unassigned**. The editor heading names the selected state. Inactive or disconnected saved mappings never claim a current hardware ACK; an invalid inactive target does not interrupt other rows.
- The Mapping section has its own 24px **× / ✓ Cancel / Apply** actions. It calls one existing `ConfigureControl` API after validating a fresh draft. Range/Mode semantics require hardware re-LEARN; a HW Type-only PUSH/TOGGLE adapter change retains the ACK. **HW Type** is the host-declared PUSH/TOGGLE receive adapter; changing it does not write controller configuration and is not hardware auto-detection. Native Menu/Toggle/Pulse use fixed compatible Mode/Range; Float/Int knobs permit validated Range edits. Python registration callbacks support compatible Toggle/Pulse modes. Cancel discards only the Mapping draft. Configuration uses its own commit and never writes Value.
- Value edits live for a valid non-Pulse target on the active Device: numeric fields with a compact **Float ↔ / Int ↔** cycle button, a native Menu dropdown, or an ON/OFF Toggle. Numeric input initially follows the target Style; click to switch input type for this editor selection. Switching never writes or rounds the target Value, changes native Style/range, or requires re-LEARN. Int input accepts whole numbers; a native Int target still rejects fractional values in Float input. Choosing another slot defaults to its native type. Pulse stays read-only. User text edits call the existing `SetValue` API immediately, with no Value Apply/Cancel. Incomplete/invalid/out-of-range text never writes. Model/controller updates refresh the field when it is not being edited and do not echo a write. Inactive Devices are browse-only but their parameter values update live.
- **HW Learn** directs the user to the controller's LEARN button. Hardware LEARN changes the surface and displays `LEARN MODE ON`; this UI does not invent a hardware learning state.
- **Ping (signal icon)** (top right) reoffers the selected control's existing mapping metadata through `Offerparameter`, including a registration whose hardware mapping was forgotten. Connect to PLUGIN, open hardware LEARN, select the matching knob/button and click Ping. `Awaiting hardware ACK` means sent, not learned. It does not change Value or fire Pulse actions.
- **⌫ Clear** (top right) removes only the selected registration through `RemoveControl`, preserving its target parameter and Value. Click once to show an inline question, then click **?** within eight seconds to confirm. Cancel, selecting another control, context/session/metadata changes or another action invalidate confirmation. Exit LEARN and release the control first. Offline removal uses the existing controller's pending unmap behavior on reconnect; hardware unmap has no ACK.
- **× Cancel / ✓ Apply** belong to Mapping; the picker has its own **× Cancel / ✓ Assign**, plus previous/next and Refresh actions. Value has no Apply/Cancel. Ping/Clear remain top right; all actions are 24 × 24 using TD’s bundled Material Design Icons font (access-point, backspace-outline, close and check). Clear confirmation uses help-circle-outline from the same font. The Value status row uses the full width. Clear confirmation keeps its question visible during hover.

The Inspector is **240 × 390** at its default content size. Native resizing retains window dimensions, but text/icon deformation during dragging remains unresolved in both the main Inspector and Popup; this is deferred as [issue #6](https://github.com/joshuahhn/roto_control/issues/6). The Popup initially aligns beside the Inspector; its width and height resize independently, with **Size from Window** enabled and fixed aspect off. Default size is **240 × 178**; later selection does not resize/reposition an open Popup to match the main window. Editors use 12px side insets and 6px gaps between rows and adjacent controls; Mapping Cancel/Apply align with their own description. Mapping is collapsed by default, retaining the 178px editor. Expanded editor content is 312px: Fold expands inside the main list; Popup adds 134px to its current native height downward, preserving width, top-left and the upper fields. Manual native width is synchronized before any position/height settings so section changes cannot temporarily restore the stale opening width. Opening-size/offset parameters update an open Popup directly; section changes do not pulse Open/Close or reopen the window. Collapsing removes only that section height; manual resizing becomes the new base size. The target picker uses 428px content and opens separately from Mapping; Popup adds/removes its 250px section delta, while Fold uses the existing scrolling list. The main Inspector stays unchanged. Its native window can still be resized manually, and a smaller viewport retains scrolling. `fit_editor_height.py` trims an existing Popup to its current content height once, without locking later manual resize. The main header stays pinned; both scroll areas use mouse-wheel scrolling or the native scrollbar. Changing a live Value or Mapping retains an already opened Popup for reuse; the native X or `DismissPopup()` closes it. No editor is opened automatically during startup or verification cleanup.

## Shared model

`live_model.py` projects the existing controller catalog and Layout registry. The controller remains authoritative. One shared model supplies both views, with a four-context LRU and bounded derived source/info/revision entries. Active data comes from `GetControlCatalog`; inactive data resolves saved targets and reads their current parameters. Neither browsing nor cache eviction changes mappings, values or the routing context.

Existing catalog DAT changes and exact parameter watchers schedule a coalesced frame-end sync. Watched owners/parameters follow subscribed contexts, including inactive Devices. There is no added permanent per-frame polling DAT. Equal data does not notify views; equal display text is not written. Closed Inspectors defer value text writes and catch up on reopen. A burst of 1,000 sync requests retains one pending run.

`ui.py` keeps selection, scroll, picker state, Mapping draft and last displayed text local to each view. Generation/context/slot/revision tokens reject stale Mapping commits and Value editing scopes after session or metadata changes. Hardware value traffic leaves metadata tokens valid. Only user text callbacks dispatch Value; programmatic Text COMP changes never do. Equal Value writes are no-ops. Weak subscriptions and callback-specific unsubscribe prevent an old extension's destruction from unregistering its replacement.

`commands.py`, embedded in `base_commands/InspectorCommands`, owns shared health/capability rules and guarded Value/Assign/Configure/Ping/Clear execution. The promoted command extension resolves the current model on each call, including after reload. Touch/LEARN health changes update action availability without expiring a Value draft; mapping, input adapter and native definition changes expire it. Readonly, unsupported evaluation modes and invalid clamp ranges block Value/Ping while permitting guarded registration cleanup.

Native definition snapshots have a separate four-context LRU containing scalar metadata, not retained Par handles. They refresh on editor open, mode events, changed catalog metadata and before commands; session/controller detachment clears the cache. Definition changes without native events are rechecked on open/action. BIND master owners join exact watchers. Equal editor capability snapshots avoid repeated control writes; no RX/TX counter watcher or permanent frame polling is added.

`target_catalog.py`, embedded in `base_targets/TargetCatalog`, supplies cancellable on-demand discovery with two jobs, one continuation each, a cooperative 2ms slice budget, 32 scope/kind snapshots and 4,096 total cached candidates. Six reused result rows per host page through results. Typing filters the current snapshot without tree scans; explicit Refresh rebuilds it. Candidate definitions are revalidated before Assign. Controller/session detachment cancels jobs and clears cache; export also clears hidden result labels and scope/query.

`model.py` remains the foundation and original mock catalog for isolated synthetic tests. Its eight-context fixtures are separate from real controller data; live mode rejects fixture updates, snapshots, resets and restores. Historical synthetic stress reports do not establish performance for every real controller workload.

## Exports and builders

Load `inspector_model.tox` first, then either view export. Set the model's **Data → Controller** OP parameter to an existing Roto controller. The generic exports have no controller reference, saved target IDs/destinations or user mappings. Python is embedded; no external source file is read at runtime. Reconnecting the hardware remains the production controller's responsibility.

`build_model.py` and `build.py` create the original demo layers. `build_live.py` attaches them to an existing controller and installs the live adapter without rebinding or restarting the production extension. Execute builders in a separate namespace when using `exec`:

```python
from pathlib import Path
namespace = dict(globals())
exec(Path(project.folder + '/prototypes/inspector/build_live.py').read_text(), namespace)
```

`export_live.py` temporarily detaches only the UI read adapter, clears exported draft/selector data, saves all three components through live TD and restores the adapter. It never disconnects production MIDI or writes target parameters. `verify_live_exports.py` reloads those generic UI exports and restores the link, verifying that the production session/catalog remains unchanged. Never edit `.toe` or `.tox` binaries directly. `inspector_demo.tox` is the older combined design.

## Editor dropdowns in the existing window

Value Menu, Mapping Mode and HW Type now use the same compact in-window rows as the accepted Device/Layout/Track selectors, in both Fold and Popup. Numeric Float/Int remains a cycle button. The Target picker retains its inline search panel. Each view has three fixed eight-row pools (main, Fold editor, Popup editor), with only one menu active. Editor dropdowns always open downward. If the existing Window/viewport height fits the choices, it shows all pooled options (up to eight). Otherwise it shows up to four visible rows with count, wheel and paging arrows. The editor adds only the missing compact height. Popup uses existing free height first and grows downward only when necessary, preserving width/top-left without reopening the Window. Selection/dismissal restores the extra height. Fold adds space within its existing scrollable content; the main Window size stays unchanged.

Clicking an item closes the dropdown before invoking its guarded callback. Value writes live; Mode/HW Type edit only the Mapping draft until Apply. Session, target token, Menu definition and menu-generation checks reject stale callbacks. Outside click, Escape, focus loss, selection changes and Disconnect dismiss the active menu within its own window scope. Generic exports scrub all three pools and keyboard buffers, and normalize closed Popup content/Window height to 178px so a same-frame close cannot retain expanded empty space after reload.

`editor_dropdown_verification.json` records staged native press/release tests on a disconnected Menu/callback controller fixture: both styles select on the first item press, open downward, grow/collapse the editor, preserve Window width/top-left/open count, dispatch live Value and retain draft-only Mapping. The production catalog, registry, session and routing survive unchanged; the fixture is removed afterward. Fresh external builder and generic reload checks also pass. Automated gestures do not substitute for the user's physical mouse acceptance of the editor controls. Native drag deformation remains deferred in issue #6.

The saved Popup had retained 551px of height for 178px of collapsed content. `fit_editor_height.py` trims this excess once while retaining manual width and subsequent free resizing; it closes any dropdown before fitting and never pulses Open on an existing Window. The compact Menu editor uses 178px collapsed / 270px with four visible downward choices and paging. A manually taller editor can show all eight choices without further Window growth.

## Popup lifecycle height fix

Rapid collapse/close/reopen previously adopted a stale expanded viewport cache and added 134px on every Mapping cycle. The view now retains the latest intended geometry while native Window and Size From Window settle, uses it for reopening and dropdown space decisions, then clears it with one cancellable three-frame callback. Disconnect/export cancel the callback. No permanent frame poll or new Window is added. Manual dimensions after settlement remain the base. Twenty native reopen cycles, thirty rapid section cycles and manual-size checks pass; see popup_reopen_height_before.json, popup_reopen_height_after.json and [REPLACEMENT_REPORT.md](REPLACEMENT_REPORT.md).

The first 30-minute acceptance soak stopped at 352 seconds upon finding this height bug. Its capture is partial, with replacement not accepted; real data is restored. The user reports physical Mapping Range re-LEARN has not yet been tested.
